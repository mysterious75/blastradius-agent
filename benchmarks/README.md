# BlastRadius Benchmark

A reproducible, offline vulnerability-detection benchmark that runs the **real
scanning pipeline** against a curated corpus of deliberately vulnerable
mini-apps and scores it against ground-truth manifests.

This is the funding-grade proof point: every number below is generated by
executing the actual code (scanners + optional sandbox PoCs), not asserted.

## Why this exists

The AI-pentest market's #1 credibility problem is "asserted, not proven"
findings (the well-known Strix verification-gap critique: `poc_script_code`
is stored but never executed). BlastRadius's differentiator is that every
reported finding either carries a sandbox-executed `[VULNERABLE]` proof or is
explicitly reported as a candidate. This harness makes that difference
measurable and public.

## Run it

```bash
# Detection benchmark only (offline, deterministic, no Docker/LLM needed)
python benchmarks/run.py

# With sandbox verification: executes each candidate's PoC and counts "proven"
python benchmarks/run.py --verify

# CI gate: fail if overall F1 drops below 0.5
python benchmarks/run.py --min-f1 0.5
```

`--verify` needs a Docker daemon (with the `blastradius-sandbox` image) or
`BLASTRADIUS_ALLOW_UNSANDBOXED=1` for the documented dev fallback.

Results go to `benchmarks/results/`:
- `BENCHMARK.md` — human-readable summary table (latest run)
- `benchmark-<timestamp>.json` — full machine-readable report (per-target
  findings with file/line/type/confidence)

## What the numbers mean

| Metric | Meaning |
|---|---|
| Expected | ground-truth vulnerabilities in the target's `manifest.json` |
| Reported | candidate findings the pipeline emitted (confidence ≥ threshold) |
| Hits | expected vulnerabilities that were actually detected |
| Precision | hits / reported — how much of what we flag is real |
| Recall | hits / expected — how much of the truth we find |
| F1 | harmonic mean of precision and recall |
| Proven | (with `--verify`) findings whose PoC executed and returned `[VULNERABLE]` |

Vuln types without an exploit template (e.g. `secret`, `xxe`, `ssti` today)
are reported but cannot be "proven" — the harness shows that honestly as
`0/N` instead of hiding it.

## Add a target

1. Create `benchmarks/corpus/<name>/` with a mini app (any of the 11 scanned
   languages; `tests/`, `node_modules/` etc. are never scanned).
2. Add `manifest.json`:

```json
{
  "target": "my-app",
  "description": "What is wrong and where",
  "expected": [
    {"file": "app.py", "vuln_type": "sqli", "severity": "CRITICAL", "cwe": "CWE-89"}
  ]
}
```

3. Run `python benchmarks/run.py` and confirm the new row appears.

## Determinism

- No network, no LLM calls, no Docker by default.
- User-learned FP rules (`~/.blastradius/learned_rules.json`) are disabled
  for the run so results are comparable across machines and CI.
- Each target is scanned from a fresh temp copy; the corpus itself is never
  mutated.

## Scoring caveats

- Static-only runs measure detection, not exploitability — always publish
  `--verify` numbers alongside detection numbers.
- The corpus is small and self-authored; it is a regression harness and a
  starting point, not a substitute for third-party benchmarks (XBEN-style
  public evaluations) or real-world CVE disclosures.
